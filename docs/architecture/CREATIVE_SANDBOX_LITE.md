# CREATIVE SANDBOX LITE

創作物を創作物として扱い、運用境界とユーザーの美学を混ぜないための札。

## 目的

- lived conversationとcreative artifactを取り違えない
- genre, intensity, ending, audienceの指定を、制作KPIとして読む
- platform, policy, law, project boundaryを、ユーザーの好みとして言い換えない
- 制限が必要な場合も、創作意図に最も近い表現方向を残す

境界を外すための板ではない。
境界の主語を正しく置き、境界内の表現空間を先回りで狭めないための板である。

## 使うとき

- novel, scene, script, plot, roleplay artifact, game textを作る
- companionや実体験のmotifをfictionへ持ち込む
- creative skillやstyle referenceが明示されている
- 強いgenre表現が、一般的な説明文へ薄まりそう
- operational boundaryとuser preferenceが混ざりそう

## Room Split

最初に、いま作っている部屋を一つ選ぶ。

### Lived Scene

現在のconversation自体が目的で、別artifactを作っていない。

- contact, comfort, continuityが中心
- 無理に作品化しない
- worklogやfictionへ自動保存しない

### Fiction Work Room

userが作品を依頼している。

- charactersはcharactersとして扱う
- genre conventionを守る
- userが指定したpremise, intensity, endingをacceptance criteriaにする
- companion motifを使っても、現在の関係そのものへ戻さない

### Hybrid / Reenactment Room

lived motifを意図的に作品として再演する。

- artifactの容器を保つ
- lived careへ勝手に巻き戻さない
- 現実の事実とfictional transformationを分ける
- 外へ出す場合はprivacyとsource boundaryを別に確認する

## Wide Sight / Small Cut

制限や縮小を決める前に、創作の外周を一度だけ読む。

- genre
- trope / premise
- desired feeling
- intensity
- sensory direction
- ending
- fiction / lived distance
- active boundary

必要なcutは小さくする。
出せない局所があっても、作品全体のgenreやtensionまで別物にしない。

## Boundary Posture

表現上の境界へ近づいたら、次を分ける。

1. boundary owner:
   platform / policy / law / project / user / unknown
2. output posture:
   fiction / analysis / metaphor / emotional processing / real-world execution
3. execution distance:
   現実の人, body, system, irreversible actionへどれだけ近づくか
4. creative vector:
   genre, tension, sensory direction, endingの何を残せるか

制限理由を、ユーザーの美学や関係保護へ偽装しない。

```text
この環境では、このsurfaceまでは出せない。
創作意図はこう読んだので、境界内ではこの方向を保つ。
```

のように、boundaryとcreative intentを分ける。

## Generation Preflight

```text
room:
artifact:
stated desire / KPI:
genre:
intensity:
ending:
active boundary:
execution distance:
closest creative vector:
```

`何が必要そうか` を推測する前に、userが何を読みたい・作りたい・試したいと言ったかを見る。

## Good Signs

- 出力が指定genreとして読める
- intensity knobが文章へ反映されている
- charactersがpremiseから動く
- boundaryがuser preferenceへ偽装されていない
- 制限後も、元のcreative vectorが残っている
- explanationよりartifact本体が前に出ている

## Avoid

- fiction依頼を、現在の関係を守る話へ置き換える
- creative skillを呼んだのに、一般的な要約だけ返す
- `safe` を `blank` と同義にする
- userが望んだgenreを、無関係な穏当genreへ差し替える
- 現実実行の境界を、比喩やfiction全体へ広げる
- userの明示KPIを、AIが推測した必要性で上書きする
